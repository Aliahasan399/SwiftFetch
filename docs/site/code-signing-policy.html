Attribution

Free code signing provided by SignPath.io, certificate by SignPath Foundation

The certificate used for signed SwiftFetch releases is issued to SignPath Foundation, which is therefore the publisher shown by Windows. This policy is published to document that relationship and the controls applied to each signing request.

Team roles

The project is maintained by a single person who currently performs all three signing roles. The role holders are:

  • Authors: [OWNER: author name or GitHub team link]
  • Reviewers: [OWNER: reviewer name or GitHub team link]
  • Approvers: [OWNER: approver name or GitHub team link]

Contributions are accepted through reviewed changes. The CI workflow submits signing requests; an Approver must approve every release signing request. All role members use multi-factor authentication for repository and signing-service access.

Release signing process

Release builds are produced by GitHub Actions on GitHub-hosted runners from the public repository's main branch with a pinned Rust toolchain and locked dependencies. The signing service verifies build origin from GitHub metadata. Only artifacts built from the repository are eligible for signing, and each release requires manual approval before a signature is applied. Test builds use a separate test-signing policy and are never signed with the release certificate.

Privacy policy

This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. Third-party components and services are described in the project's third-party notices and the Privacy page.
