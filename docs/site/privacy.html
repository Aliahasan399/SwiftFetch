This notice reflects the release-candidate implementation. Before publication, the release owner must identify the publisher, provide a privacy contact, choose support and retention procedures, and review this notice against the actual release configuration. It does not claim regulatory certification.

Privacy

SwiftFetch is local-first. It does not require an account and does not upload telemetry for downloading.

What is stored locally

Queue state, settings, filenames, destination paths, download URLs and request metadata are stored on the local Windows account. By default, data is kept in the current user's %APPDATA%\swiftfetch directory. Downloads go to the destination you choose. The environment variables SWIFTFETCH_DATA_DIR, SWIFTFETCH_DB_PATH and SWIFTFETCH_DOWNLOADS_DIR can override the defaults.

A URL or request header can contain private access tokens. Local database backups must therefore be kept private.

Network activity

The application makes network requests to download sources, configured proxies and redirects accepted by its URL policy. A publisher-configured update check contacts the release endpoint only when requested. No cloud account or telemetry upload is required for downloading. Local diagnostic exports do not upload themselves.

An unconfigured build makes no release network request. Signed updates require publisher configuration; see Documentation.

Clipboard capture

Clipboard monitoring is off by default. When enabled, it reads clipboard text locally to detect a permitted HTTP(S) URL and opens a confirmation form; detection alone does not start a transfer. The explicit Paste URL button reads the clipboard for that action. Disable capture in Settings to stop monitoring.

Browser extension

The optional extension sends the selected URL to the local app through Windows Native Messaging only after a user action. It does not forward browser cookies or credentials. Unpacked extension setup and native-host registration are optional. The extension has no broad host permissions, does not inspect page content or network traffic, and its logs contain only scheme and host, with paths and queries stripped.

History, retention and sharing

History clearing and automatic retention remove queue metadata, not completed files. Optional failed-partial cleanup is limited to the working file owned by the failed task. An explicit Skip decision removes that task's new working file and keeps the existing destination file unchanged.

A shareable queue inventory excludes request URLs and headers but includes filenames and local paths. Review it before sharing. A full local SQLite backup contains private request data and is not a support attachment by default.
