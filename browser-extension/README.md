# SwiftFetch — Browser Extension

**Current Windows candidate:** follow [SETUP.md](SETUP.md). The release uses the
installed SwiftFetch executable as its Native Messaging host. Build the extension
with `node browser-extension/tools/package.mjs`; use the generated self-contained
folder, then register the executable with `tools/register-host.ps1`.

The Python/HTTP/shared-secret design below describes an earlier prototype. It is
retained as development history and is not the setup for this candidate.

<details>
<summary>Historical prototype design and tests</summary>

Browser bridge for SwiftFetch, the IDM-style Windows download manager.

The extension captures a download **only** when the user performs an explicit
action, validates the resulting message against a strict wire protocol, and
hands it to the SwiftFetch desktop app through a native messaging host and an
authenticated loopback HTTP call.

It never inspects page content, never observes network traffic, and never sends
cookies, authorization headers, or credentials.

---

## 1. Message flow

```text
user gesture (Alt+Click / context menu / popup button)
        |
        v
chrome/content.js          gesture detection only, no page reads
        |  chrome.runtime.sendMessage
        v
chrome/background.js       authoritative validation (shared/protocol.js)
        |  chrome.runtime.sendNativeMessage
        v
native-host/host.py        re-validation, replay cache, HMAC signing
        |  POST http://127.0.0.1:27642/bridge/intent
        v
SwiftFetch app (Rust)      add_download
```

Every layer validates again. A message that fails anywhere is dropped and the
user sees a safe error message.

## 2. Wire protocol

`shared/protocol.js` is the single source of truth for the envelope and its
validators. `native-host/host.py` mirrors every rule.

```json
{
  "protocol": 1,
  "type": "download_intent",
  "request_id": "3f6f8b2e-9c4a-4c1e-9a2b-7d5e6f7a8b9c",
  "url": "https://example.com/file.zip",
  "suggested_name": "file.zip",
  "page_origin": "https://example.com",
  "content_type": "application/zip",
  "user_initiated": true,
  "cookies": [],
  "expires_at": "2026-11-09T12:04:00.000Z"
}
```

Rules enforced in `validateIntent` / `buildIntent`:

| Rule | Behaviour |
| --- | --- |
| Schemes | `http:` and `https:` only. `file:`, `javascript:`, `data:`, `blob:`, `ftp:`, `ws:` and custom schemes are rejected. |
| URL size | Maximum 2048 characters. |
| URL characters | Control characters and whitespace rejected. |
| URL credentials | Embedded `user:pass@host` rejected. |
| `suggested_name` | Reduced to a basename. `..` segments rejected, drive/UNC paths rejected, Windows device names (`CON`, `NUL`, `COM1`, …) rejected, characters invalid on Windows replaced, trailing dots rejected, length capped at 200. |
| `cookies` | Must be an empty array unless the caller passes `allowCookies: true`. **The shipped extension never passes it.** |
| Sensitive fields | `authorization`, `proxy-authorization`, `cookie`, `headers`, `credentials` are rejected before anything else, as is any unknown field. |
| `user_initiated` | Must be exactly `true`. Passive capture is rejected. |
| `expires_at` | ISO 8601, must be in the future and within 5 minutes. |
| `request_id` | UUID version 4. Duplicates within the 5-minute replay window are rejected. |
| `page_origin` | Bare `http`/`https` origin: no path, query, fragment, or credentials. |
| `content_type` | `type/subtype`, defaults to `application/octet-stream`. |

Failure shape:

```json
{ "ok": false, "code": "invalid_scheme", "message": "scheme \"file:\" is not allowed" }
```

## 3. Layout

```text
browser-extension/
  shared/protocol.js          envelope + validators (JS, shared by every layer)
  chrome/
    manifest.json             Manifest V3
    background.js             service worker, authoritative validation
    content.js                gesture detection only
    popup.html, popup.js      enable/disable, per-site rule, "send to SwiftFetch"
    icons/16|32|48|128.png     generated by tools/generate_icons.js
  firefox/
    manifest.json             Manifest V2 (background.scripts)
    background.js             MV2 worker, same behaviour, callback-safe chrome.* calls
  native-host/
    com.swiftfetch.app.json   Chrome/Edge host manifest template
    swiftfetch_native_host.bat  Windows launcher (native messaging needs an .exe/.bat)
    host.py                   Python native messaging host
  test/
    test_protocol.js          node --test suite, 66 tests
    run_tests.sh              wrapper
    test_page.html            manual gesture harness
  tools/generate_icons.js     dependency-free PNG icon generator
```

The Firefox package reuses `chrome/content.js`, `chrome/popup.html`,
`chrome/popup.js` and `chrome/icons/` through relative manifest paths, so there
is one implementation of the gesture logic.

## 4. Loading the extension

### Chrome / Edge (Manifest V3)

1. Open `chrome://extensions` (or `edge://extensions`).
2. Enable **Developer mode**.
3. Click **Load unpacked** and select `browser-extension/chrome`.
4. Note the extension ID shown under the extension name.

### Firefox (Manifest V2)

1. Open `about:debugging#/runtime/this-firefox`.
2. Click **Load Temporary Add-on…**.
3. Select `browser-extension/firefox/manifest.json`.
4. The add-on ID is `swiftfetch@localhost` (from `applications.gecko.id`).

To load the Firefox build permanently, sign it with `web-ext sign` or package it
as an XPI; MV2 temporary add-ons disappear on restart.

### Icons

Regenerate with:

```sh
node browser-extension/tools/generate_icons.js
```

## 5. Native messaging host

### Host manifest

`native-host/com.swiftfetch.app.json` is the Chrome/Edge template. Change two
things before registering it:

1. `path` — the absolute path to `swiftfetch_native_host.bat` (native messaging
   cannot launch a `.py` file directly).
2. `allowed_origins` — your extension ID:
   `"chrome-extension://<your-extension-id>/"`.

Firefox uses the same file with a different key:

```json
{
  "name": "com.swiftfetch.app",
  "description": "SwiftFetch browser bridge native messaging host",
  "path": "C:\\Program Files\\SwiftFetch\\swiftfetch_native_host.bat",
  "type": "stdio",
  "allowed_extensions": ["swiftfetch@localhost"]
}
```

### Registration (Windows registry)

Create the given key and set its `(Default)` value to the full path of the JSON
file. Do not put the JSON next to the executable and expect discovery — the
registry entry is required.

```text
Chrome   HKEY_CURRENT_USER\Software\Google\Chrome\NativeMessagingHosts\com.swiftfetch.app
Edge     HKEY_CURRENT_USER\Software\Microsoft\Edge\NativeMessagingHosts\com.swiftfetch.app
Firefox  HKEY_CURRENT_USER\Software\Mozilla\NativeMessagingHosts\com.swiftfetch.app
```

PowerShell example (run as the current user):

```powershell
New-Item -Path "HKCU:\Software\Google\Chrome\NativeMessagingHosts\com.swiftfetch.app" -Force
Set-ItemProperty -Path "HKCU:\Software\Google\Chrome\NativeMessagingHosts\com.swiftfetch.app" `
  -Name "(Default)" -Value "C:\Program Files\SwiftFetch\com.swiftfetch.app.json"
```

### Environment variables

Set these for the user that runs the browser.

| Variable | Required | Default | Meaning |
| --- | --- | --- | --- |
| `SWIFTFETCH_SHARED_SECRET` | yes | — | HMAC key shared with the SwiftFetch app. Never log or commit it. |
| `SWIFTFETCH_APP_URL` | no | `http://127.0.0.1:27642/bridge/intent` | Loopback endpoint of the app. Must be `http` on `127.0.0.1`, `localhost`, or `::1`. |
| `SWIFTFETCH_HOST_LOG` | no | `%LOCALAPPDATA%\SwiftFetch\native-host.log` | Log file. Never stdout: stdout is the protocol channel. |
| `SWIFTFETCH_MAX_BODY` | no | `1048576` | Inbound message cap in bytes. |

The launcher refuses to start without `SWIFTFETCH_SHARED_SECRET`.

### Verifying the host by hand

The host speaks the Chrome native messaging framing: 4-byte little-endian length,
then that many bytes of UTF-8 JSON.

```sh
printf '\x3e\x00\x00\x00{"protocol":1,"type":"download_intent"}' | python host.py
```

Any valid invocation returns a length-prefixed JSON reply. Without a running app
the reply is `{ "ok": false, "error": { "code": "app_unreachable", ... } }`.

## 6. App-side contract (Rust)

The desktop app must expose the loopback bridge the native host calls.

```text
POST http://127.0.0.1:27642/bridge/intent
Content-Type: application/json
X-SwiftFetch-Request-Id: <request_id>
X-SwiftFetch-Timestamp: <unix seconds>
X-SwiftFetch-Signature: <hex HMAC-SHA256>
X-SwiftFetch-Host-Version: 1

<the validated download_intent envelope>
```

Signature input, in this exact order, as UTF-8 bytes:

```text
"<timestamp>.<request_id>." + raw request body
```

The app must:

1. Bind to loopback only.
2. Recompute the HMAC with the shared secret and reject mismatches.
3. Reject timestamps more than 5 minutes old.
4. Reject a repeated `request_id` within 5 minutes.
5. Map the intent onto `add_download` (`url`, `suggested_name`,
   `headers: []`, `start_policy: "immediate"` or `"manual"` per settings).
6. Never log cookies, authorization headers, or the full URL path/query.

Reply shape:

```json
{ "ok": true, "task_id": "…" }
```

```json
{ "ok": false, "error": { "code": "invalid_url", "message": "…", "retryable": false } }
```

The extension surfaces `code` and `message` verbatim, so keep messages free of
secrets and full URLs.

## 7. Testing

```sh
node --test browser-extension/test/test_protocol.js
# or
bash browser-extension/test/run_tests.sh
```

The suite covers every rule: scheme allow/deny lists, URL length and control
characters, basename reduction, traversal, reserved Windows device names,
cookie opt-in and caps, `user_initiated`, expiry and TTL, replay protection,
origin normalization, UUID v4 shape, unexpected and sensitive fields, content
type, canonical output, and log redaction.

### Manual harness

```sh
cd browser-extension
python -m http.server 8000
# open http://127.0.0.1:8000/test/test_page.html
```

The page reports whether the content script loaded, offers Alt+Click targets
(including a `javascript:` link that must be refused), and exposes
`window.__swiftfetchSend(url, name)` so a gesture can be simulated from the
console.

### Icons

```sh
node browser-extension/tools/generate_icons.js
```

Writes `chrome/icons/{16,32,48,128}.png` using only `node:zlib`.

## 8. Privacy posture

- No `host_permissions`, no `<all_urls>` network access, no `webRequest`.
- The content script registers listeners only. It never enumerates links, never
  reads page text, and never touches `document.cookie`.
- `tabs` permission is used solely to read the active tab's URL when the popup
  is opened by the user.
- Nothing is sent without a gesture, or a per-site rule the user configured.
- Logs contain scheme + host only. `redactForLog` strips path and query.

## 9. Limitations

- The extension does not capture downloads that the browser starts on its own;
  it only handles deliberate user actions, by design.
- `suggested_name` is a hint. The app owns final naming and destination policy.
- The native host requires a Python 3.7+ interpreter on `PATH` (or an edited
  launcher).
- No packaged build or store listing is included; loading is unpacked only.
